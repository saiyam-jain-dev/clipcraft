HOW OPUS-STYLE CLIPPING ACTUALLY WORKS (build this, do not clone their servers)
================================================================================
Public product claims (homepage + FAQ, observed 2026-11-19), and the engineering that produces that result:

A. Ingest
   - Link or file. Hosts they advertise: YouTube, Google Drive, Vimeo, Zoom, Rumble, Twitch, Facebook, LinkedIn, Twitter/X, Loom, Riverside, StreamYard.
   - We already download with yt-dlp (see core/downloader.py) and accept local uploads.

B. Understand the whole video, then pick moments
   - Speech: transcribe with word timestamps (we use faster-whisper).
   - Group words into sentences. A clip is a contiguous sentence range, not a random time window.
   - Score each candidate on four things Opus-style editors care about:
       hook  = first line stops the scroll (claim, question, number, conflict, emotion)
       flow  = a stranger understands it and it ends on a conclusion, not mid-thought
       value = story, insight, humor, or emotion
       trend = energy, pace, and whether it feels like a short
   - Audio loudness spikes (laughter, shouts) and, when speech is thin, visual motion (cuts, action) are extra signals. Opus markets "ClipAnything" for vlogs, gaming, sports, interviews — not only podcasts. Our highlights / energy path is the local version of that.
   - An LLM (Gemini or Groq) reads the numbered transcript and returns sentence ranges + titles. Heuristics are the fallback when there is no API key. The LLM is NOT shown the video pixels today. That is acceptable for talking videos. Visual-only videos use motion/energy.

C. Reframe
   - 16:9 source becomes 1080x1920.
   - Face detection (YuNet) chooses fill (follow the face), fit (full frame on a blurred background), split (two people), or gameplay (face on top, screen below).
   - Opus calls this ReframeAnything. Ours is OpenCV sampling every 0.5s, not a learned tracker. Good enough; do not claim pixel-perfect tracking.

D. Finish
   - Karaoke captions burned in (ASS).
   - Thumbnail, MP4, SRT.
   - YouTube title/description and Instagram caption. Nothing is posted.

E. What we will not build unless the user asks
   - Accounts, payments, team workspaces, brand-template editor, one-click publish to YouTube/Instagram/TikTok, trend-scraping "big data", manual timeline editor.

================================================================================
ARCHITECTURE MAP
================================================================================
server.py
    Flask routes. Validates URL host, options, uploads. Job API. Settings. Social package.
    POST /api/clip  {url or video_file, crop_mode, focus, target_clips, min/max duration, range, captions, prompt, language}
    GET  /api/jobs/<id>   poll this
    GET  /api/video-info?url=
    GET/POST /api/settings

core/pipeline.py
    download → extract wav → whisper → sentences → energy (+ motion if sparse speech or focus=highlights)
    → find_viral_moments → render each clip → append to job JSON as it finishes.

core/virality_engine.py
    THE moment picker. Heuristic candidate search, LLM picker, energy/visual fallback.
    find_viral_moments() is the only entry point.

core/llm.py
    Gemini generateContent or OpenAI-compatible /chat/completions. JSON only.

core/transcriber.py
    faster-whisper, word timestamps, disk cache downloads/transcript_*.json

core/downloader.py
    yt-dlp + ffmpeg audio extract. Local file path is also a valid source.

core/face_tracker.py
    YuNet or Haar. analyze_video_speakers() picks layout. activity_profile() for motion.

core/renderer.py
    ffmpeg filter graph. 1080x1920. NVENC if present else libx264.
    Layouts: fill (default crop+track), fit, split, gameplay. auto uses face_tracker mode.

core/subtitle_engine.py
    Karaoke ASS.

core/publisher_engine.py
    Social copy from clip fields. No network publish.

core/branding_engine.py
    Optional text watermark.

core/jobs.py
    JSON files in jobs/. One background worker thread. A job left "processing" by a dead server is marked failed on next load.

core/config.py
    Paths, settings.json, 1080x1920, ffmpeg from imageio_ffmpeg.

templates/index.html + static/app.js + static/style.css
    Studio (link or upload), direction (focus, framing, count, length, captions), job progress, clip cards, projects, settings dialog, social copy dialog.
    JS polls /api/jobs/<id>. Clips appear as each render finishes.

jobs/*.json          persisted projects
outputs/             rendered mp4, jpg, srt, ass
downloads/           source video, wav, transcript cache
uploads/             user file uploads

KNOWN QUALITY BUG (must stay fixed)
================================================================================
Job jobs/eeab9da087.json completed with engine fallback (no AI key) and produced bad hooks:

    clip 1 title: "Anyway, today I'm a writer, blogger, guy."
    clip 2 title: "A less pleasant place, but where really important things happen."
    both reasons: "Self-contained story with a clean beginning and ending."

Cause: _heuristic_clips() correctly skips weak openings, then if it cannot fill `target` it calls _heuristic_clips_relaxed(), which dropped the weak-open check. "Anyway..." matches FILLER_START and should never be a clip start. "A less pleasant place..." is a continuation (referential / no hook) and scored well only because flow outweighed hook.

Required behavior:
    - Never start a speech clip on filler (um, so, anyway, welcome, thank you) or on a pronoun/this/that sentence that needs the previous line.
    - Titles come from the sharpest line in the range (_headline), not the weak first sentence.
    - Relaxed mode may relax "previous sentence must be terminal" and the hook>=68 gate. It must NOT relax the weak opening.
    - If the strict pass finds fewer clips than requested, return the good ones. Do not pad with bad openings.
    - When an AI key exists, LLM ranges still pass through _fit_bounds and the weak-open reject in _llm_clips.

A code fix for the relaxed-path weak opening was started on 2026-11-19. Verify it, and add a tiny unit-style check if you touch this file again: a sentence starting with "Anyway" must not be chosen when a later strong sentence exists.
